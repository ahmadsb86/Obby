RISC -> reduced intstruction set (ARM: used in mobile, Apple M-chips)
CISC -> complex instruction set (x86)
NASM/GSM - types of syntaxes for x86

`BYTE` is 8 bits, `WORD` is 16, `DWORD` is 32, `QWORD` is 64
**16 Registers**  `rax`, `rbx`, `rcx`, `rdx`, `rdi`, `rsi`, `rbp`, `rsp`, and `r8`-`r15` 
lower half bits of `rax` are `eax`.  Chain continues as `rax` → `eax` → `ax` → `al`

syntax:
`operand, desination, source`

```nasm
loop: ;subroutine to sum 32-bit integer array
    add  edx, DWORD PTR [rax] ;add DWORD pointed to by rax
    add  rax, 4 ;increment rax by 4
    cmp  rax, rcx ;compare rax,rcx and put result in a flag register
    jne  loop ;jump to loop subroutine if that flag register is true
```

add is fused command if adding from memory (does load from mem in register AND add in one go)

the above loop can be unrolled (sequentially add every single element as a seperate instruction to remove unimportant iteration instructions). Often done by compiler

Function calls essentially push registers (and mem location of following instruction) onto stack (in memory)

A function can be inlined (stitch callee code inside caller) if ensured that registers don't clash.

If a function is tail-recursive (returns immediately after recursive call), it can essentially be compiled into a loop. 

```cpp
int factorial(int n) {     //NOT TAIL RECURSIVE
    if (n == 0)
        return 1;
    return factorial(n - 1) * n;
}

int factorial(int n, int p = 1) {     //TAIL RECURSIVE
    if (n == 0)
        return p;
    return factorial(n - 1, p * n);
}
```

Compilers don't optimize `switch`-based code well so instead make a branch table (addresses of potential jump locations) and do a runtime jump with `goto *table[key]`in c++

C++ specifically uses above trick in making a *virtual method table* for runtime polymorphism (method has multiple sub-class overrides, sub-class of instance determined at runtime)

CPU front-end fetches x86 instructions from memory in 32B blocks (requires padding w/ NOPs or lengthening instructions to keep hotter code within one block) and decodes to RISC-like uops

Memory usually doesn't segregate instructions from data but cache does

Inlining functions. unrolling loops completely, and too much padding of machine code  can all cause larger than necessary binary making memory a bottleneck (more cache misses)

If we know a branch is rarely taken, `[[unlikely]]` on the `if` tells the compiler to lay out the common path as subsequent instructions in continuous flow and move the unlikely body out-of-line (to be jumped to), so the usual case costs no jump.
